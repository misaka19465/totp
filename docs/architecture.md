# 架构设计

- 状态：**v0.6**（2026-10-02：全部设计决策关闭，见 requirements.md v0.6；
  口令位数放宽为 1..6，渲染按配置位数右对齐、高位留空）
- 硬件基线：STM32L031F6P6 + HT1621B + EDS826S(T)P15V3B

## 1. 主控选型结论：沿用现有硬件

**结论：STM32L031F6P6 够用，不需要换 MCU。**

| 需求 | L031 资源 | 余量 |
|------|-----------|------|
| Flash | 32 KB | 充裕（见 §9） |
| RAM | 8 KB | 充裕 |
| 种子持久化 | 1 KB 数据 EEPROM | 单点位绰绰有余 |
| 走时 | RTC + 32.768 kHz LSE（X1 已布线） | — |
| 串口 | USART2（PA9/PA10）或 LPUART1（可重映射） | 见 §6 |
| 屏 | GPIO 3 根（PA2/PA3/PA6） | — |
| **电量监测** | **内部 VREFINT + ADC（通道 17），零外部元件** | 见 §5 |
| 低压硬阈值 | PVD，7 档，Stop 下可唤醒 | 见 §5 |
| 低功耗 | Stop + RTC + RAM 保持 = 0.6 µA | 已是最优档 |
| 看门狗 | IWDG（LSI 驱动，Stop 下可用） | 无按键时的必需项 |
| TOTP 计算 | HMAC-SHA1 纯软件 | Cortex-M0+ 足够 |

唯一短板是**没有 RNG 外设**。TOTP 不需要随机数，不构成阻塞。

## 2. 两条硬约束如何塑造了架构

| 约束 | 架构后果 |
|------|----------|
| **无任何按键** | ① 应用层只剩单个点位、单个码，无 UI 状态机<br>② 串口必须自动检测插头插入（§6.2）<br>③ **必须启用 IWDG**（§7）<br>④ 无 SOS/复位逃生，任何"等待用户操作"的设计都不成立 |
| **屏幕常亮** | ① MCU 可以在 Stop 下睡觉，屏由 HT1621B 自主驱动（§4）<br>② 功耗预算被屏驱动支配，MCU 侧优化空间小但必须做干净<br>③ 需要周期重写显示 RAM 以缓解直流偏置（§4.2） |

## 3. 软件分层

按"单一职责、小文件"划分。分层依据是**变化频率**与**依赖方向**。

```
firmware/src/
├── main.c                 上电序列 + 主循环分发（唯一了解全局的模块）
├── board/
│   └── board_pins.h       引脚映射（与原理图对照的唯一出处）
├── common/
│   └── crc16.{h,c}        CRC-16/CCITT-FALSE（帧/配置/存储记录共用）
├── drivers/               只依赖 CMSIS 寄存器定义
│   ├── ht1621.{h,c}       HT1621B 三线串口
│   ├── lcd_render.{h,c}   字形表、按位/按小数点写屏
│   ├── usart2_hw.{h,c}    USART2 寄存器级字节收发（PA9/PA10，115200）
│   ├── uart_link.{h,c}    帧编解码、CRC、重同步与会话状态机
│   ├── plug_detect.{h,c}  插头插入检测（RX 边沿 EXTI 唤醒）
│   ├── nvm.{h,c}          数据 EEPROM 字级擦写（1 KB，256 字）
│   └── battery.{h,c}      VREFINT 测电量（无温度补偿）
├── app/                   纯逻辑与应用状态，只依赖 common/drivers/services
│   ├── totp.{h,c}         动态码计算（RFC 6238）
│   ├── hmac_sha1.{h,c}    哈希原语
│   ├── base32.{h,c}       种子解码
│   ├── keystore.{h,c}     EEPROM 中的单点位配置存储（已实现）
│   └── proto.{h,c}        串口协议命令层（已实现）
└── services/              横切关注点
    ├── clock_rtc.{h,c}    RTC 读写、校准、对时（已实现）
    ├── rtc_time.{h,c}     日历/亚秒/校准纯换算（已实现，主机侧测试）
    ├── power.{h,c}        Stop 模式进出、唤醒源配置（已实现）
    ├── watchdog.{h,c}     IWDG 喂狗、复位原因与故障锁存（已实现）
    └── state_indicator.{h,c}  小数点策略：状态掩码与数字位留空（已实现，主机侧测试）
```

**依赖方向单向向下**：`main → app → services/drivers → board → CMSIS`。
`drivers/` 绝不 `#include` `app/` 下的任何东西。

> NOTE: 无按键使应用层显著变薄：没有 `menu`、没有 `ui`、没有输入消抖状态机。

### 3.1 状态点映射（`state_indicator`）

四个小数点**一对一**映射到四个状态，语义与地址见 requirements.md §4：

| 点 | 地址 | 状态 | 触发条件 |
|----|------|------|----------|
| DOT1 | `0x01.COM0` | 未写入种子 | keystore 为空 / 校验失败 |
| DOT2 | `0x03.COM0` | 需要重新对时 | RTC 从未对时，或距上次对时超出阈值 |
| DOT4 | `0x0E.COM0` | 低电量 | 见 §5.4 阈值 |
| DOT5 | `0x10.COM0` | 故障 | 看门狗复位、自检失败、HMAC 异常等 |

**故障态额外动作**：清除全部数字位（显示 `------`）。
理由：故障意味着显示的码可能无效，**空屏比让参与者记录错误码稳妥**。
该动作与 §7 的看门狗复位路径配合 —— 复位原因寄存器（RCC_CSR）
中的 IWDGRSTF 是"故障"位最可靠的来源之一。

> NOTE: 故障锁存已按上述倾向落地：IWDG 复位标志（`RCC_CSR.IWDGRSTF`）与
> 自检失败写入 RTC 备份寄存器 `BKP2R`，系统复位后继续有效；只有成功的
> `SET_TIME` / `WRITE_SLOT`（proto 回 OK）才由主循环清除。

## 4. 低功耗策略

### 4.1 功耗预算的支配项

按 hardware.md H1：**屏驱动占 99% 以上的功耗**（60–120 µA，对 MCU 的 0.38–0.7 µA）。
因此低功耗策略的目标不是"省电"（省不出来），而是：

1. **不要因为 MCU 的坏习惯额外增加功耗**；
2. **让电池耗尽的时刻可预测、可提前告警**。

由于常亮是硬需求且无按键可唤醒，本设备**没有"熄屏省电"这个选项** ——
这一点已在需求层面确认（requirements.md NFR-1）。

### 4.2 状态机

```
        ┌────────────────────────────┐
        │  ACTIVE                    │
        │  16 MHz（或 MSI 低频）      │
        │  · 刷新显示                │
        │  · 计算 TOTP                │
        │  · 处理串口                 │
        │  · 采集电量                 │
        └──────┬─────────────────────┘
               │ 无事可做
               ▼
        ┌────────────────────────────┐
        │  STOP                      │
        │  RTC 走时 / 0.6 µA         │
        │  HT1621B 自主驱动屏（常亮）│
               └──────┬─────────────────────┘
               │ 唤醒源：
               │  · RTC 闹钟（三类期限取最早，见 4.4）
               │  · PA10 EXTI（插头插入）
               ▼
           回到 ACTIVE
```

**关键点：Stop 下 HT1621B 由自身振荡器继续驱动屏，显示内容不变。**
这正是"常亮"能成立的原因 —— MCU 睡觉不影响屏。

### 4.3 显示重写的必要性（新增）

HT1621B 持续用同一组波形驱动液晶，**直流分量长期累积会加速屏体老化**。
本设备是常亮设计，这个问题被放大到数月尺度（hardware.md H8）。

**对策：每 1–2 秒重写一次显示 RAM。**

- 成本：唤醒约 5 µs + 写入 12 个 nibble（66 个串行位；按 HT1621 时序下限约
  1–3 ms），平均功耗增加约 **1–3 µA**（ACTIVE 1 mA 保守估算，每 1–2 s 一次）；
- 收益：写入过程带来的电平翻转可缓解偏置累积。

> NOTE: 采用每 1–2 s 重写一次显示 RAM；实机老化验证列入 §11。

### 4.4 唤醒间隔的设计

主循环维护三类期限，空闲入睡前取**最早者**交给同一个 RTC 闹钟 A：

| 期限 | 间隔 | 目的 |
|------|------|------|
| 口令窗口边界 | **下一个 TOTP 窗口边界** | 口令更新（精确对齐，避免多余唤醒） |
| 显示重写 | 2 s；极低电量闪烁期 1 s | 直流偏置缓解（§4.3）与闪烁相位 |
| 电量采集 | 10 分钟 | 低频采样足够 |

PA10 EXTI 是独立的事件唤醒源（插头插入），不受闹钟影响。

> NOTE: 规格里的"闹钟 A/B/C"落地为**单闹钟按最早期限武装**：STM32L0 只有
> 闹钟 A/B 两个通道，而三类期限都需要整秒精度，拆成两个闹钟并不减少唤醒
> 次数，反而要维护彼此抑制关系。实现见 `clock_rtc_alarm_set()` 与 main.c；
> 触发后由 `RTC_IRQHandler` 停用闹钟，主循环重新武装。
> 入睡期限取整秒的向下取整（`floor`），唤醒只会偏早或准时，不会错过期限。

### 4.5 必须显式处理的低功耗陷阱

| 陷阱 | 后果 | 处理 |
|------|------|------|
| 未用的 GPIO 配置为浮空输入 | 输入级振荡，µA 级漏电 | 配为模拟输入（复位默认）或输出低 |
| **未连接引脚未显式配为模拟输入** | 输入级振荡，µA 级漏电 | 上电后**显式置为模拟输入**，不启用上下拉 |
| 调试外设（SWD）保持使能 | 额外数百 µA | Stop 前关闭 DBGMCU 时钟（仅产品模式） |
| 未关的外设时钟 | 按 Table 34/35 逐项计 | 进 Stop 前关掉除 LSE/RTC 外全部时钟 |
| LSE 驱动档位过高 | 多耗电流且无收益 | 用 `LSEDRV=00`（低驱动） |
| **PVD 常开** | **+0.7~1.2 µA，超过 MCU Stop 本身** | **默认关闭**，见 §5.3 |
| IWDG | +0.2~0.3 µA | **保留**（无按键时的必需项） |

## 5. 电量监测（新增，对应 FR-7）

### 5.1 方案：VREFINT 反推 VDD

STM32L031 内部有稳定带隙基准 `VREFINT`（典型 1.224 V，连到 ADC 通道 17），
而 ADC 的参考就是 VDD。因此：

```
VDD = VREFINT_CAL × 3000 mV / VREFINT_DATA
```

`VREFINT_CAL` 是出厂校准值，存于 **0x1FF80078**（校准条件 25 °C、VDDA = 3.0 V）。

**不需要任何外部元件** —— 这正好绕开了"PA0 悬空、无法外部分压"的限制。

精度：常温 ±30~50 mV（校准 ±5 mV + ADC 噪声 + VREFINT 温漂）。

### 5.2 测量时序与功耗

| 步骤 | 耗时 |
|------|------|
| 使能 VREFINT 并等待就绪 | 2–3 µs |
| ADC 稳压器上电 + 校准 + 稳定（tSTAB） | ≈ 70–80 µs |
| 单次采样 + 转换（160.5 + 12.5 周期 @ ADC 时钟 ≈ 1.05 MHz） | ≈ 165 µs |
| 单次合计 / 8 次平均合计 | ≈ 250 µs / ≈ 2 ms |

**对功耗的影响完全可忽略**：即使按 ACTIVE 电流 1 mA 保守估算，每 10 分钟一次的
≈ 2 ms 采样折算平均约 **3 nA**（整机 61–121 µA 的约 0.005%），
整个电池寿命内额外消耗 < 0.01 mAh。

### 5.3 为什么不用 PVD 常开

PVD（7 档硬件阈值）在 Stop 下可用，但**其自身电流（1.2 µA @3.0 V）
是 MCU Stop 电流（0.38 µA）的三倍多**。常开会让 MCU 侧功耗翻三倍。

**采用策略：**
- **默认关闭 PVD**；
- 电量采集用 ADC 方案（按需开启，微秒级）；
- 仅当 ADC 判定已进入低压区间后，**才启用 PVD 作为最后的硬阈值保险**，
  让它在 VDD 继续下跌时强制中断并锁定报警显示。

### 5.4 阈值

| 档位 | VDD | DOT4 |
|------|-----|------|
| 正常 | > 2.4 V | 灭 |
| 低电 | 2.2 – 2.4 V | 亮 |
| 极低 | < 2.2 V | 闪烁 |

> TODO: 阈值需实机标定：测出"对比度开始不可读"的实际电压后，更新
> requirements.md §4.1 与本表；完成条件见 §11。

> NOTE: **不做温度补偿（已定）**：VREFINT 全温区温漂折算约 6.5 mV，而本设备只是
> 提前提示换电池，常温精度（±30–50 mV）已足够；不采集内部温度传感器。

## 6. 串口与插头检测

### 6.1 外设选型

| 方案 | 时钟源 | Stop 下唤醒 | 评价 |
|------|--------|-------------|------|
| **USART2** on PA9/PA10 | 需 HSI16 或 LSE | 能，但必须保持 HSI16 | 当前引脚可行 |
| **LPUART1** 重映射到 PA2/PA3 | **可跑 LSE** | 能，保持 LSE 不增功耗 | 需改板换脚 |

**无按键使"自动检测插入"成为必需。** 但 LPUART1 用 LSE 无法承载 115200
（见 serial-protocol.md §2.3），而 USART2 的 RX 边沿唤醒已足够可靠，故
**结论：不改板换脚**（已定），保留 USART2。

### 6.2 插头检测（无按键的核心影响）

CN1 没有检测触点。可选方案：

| 方案 | 说明 | 评价 |
|------|------|------|
| **A. RX 边沿唤醒** | 空闲时 PA10 配 EXTI，检测下降沿唤醒并启动 USART | 最简；误唤醒代价可忽略 |
| B. 周期短开接收窗口 | 每 N 秒开 100 ms 窗口 | 响应有延迟，平均功耗略高 |
| C. A+B 结合 | 边沿为主，窗口为辅 | 最稳 |

**采用 A（已定）**：空闲时 PA10 配 EXTI 下降沿唤醒，唤醒后开 300 ms 接收窗口。
误唤醒时 MCU 只醒几微秒就回去睡，代价远小于 0.01 µA。

> NOTE: 当前硬件批次没有插头检测脚；将来改版若增加该脚，可改用它唤醒并简化
> 前导码流程（serial-protocol.md §3）。

### 6.3 配置模型：插上即信任（已确认）

无按键意味着无法用按键进入配对模式，设备也无法区分"组织者的上位机"和别的上位机。
本设备不是安全设备，种子也不是敏感凭据（requirements.md §1），因此**接受无鉴权**：
任何人插上都能改时间、写种子。这不是妥协，而是与用途匹配的最简设计 ——
设备在活动前由组织者受控配置，活动期间只需要持续显示正确的码。

> 不引入密码学鉴权：串口协议不需要鉴权字段。详见 serial-protocol.md §3.2。

## 7. 看门狗（新增，无按键的必然结果）

### 7.1 为什么是必需项

没有按键、没有复位按钮，**用户无法干预设备状态**。
若程序跑飞或状态机卡死，用户唯一的手段是取出电池再装回 ——
而这是一台装在壳里的常亮设备，这实际上等于设备失效。

**IWDG 是唯一的自恢复手段，因此从"可选优化"升级为"必需"。**

### 7.2 选型

| 方案 | 时钟 | Stop 下可用 | 电流 |
|------|------|-------------|------|
| **IWDG** | LSI（约 37 kHz） | **是** | +0.2~0.3 µA |
| WWDG | APB | 否 | 需 CPU 时钟 |

**选 IWDG。** 0.2–0.3 µA 相对 61–121 µA 的总预算可忽略。

### 7.3 超时时间

**初始值：4 秒魔法数，待实测调整。**

- Flash 单页擦写最长约 3.3 ms；
- HMAC-SHA1 计算 < 10 ms；
- 一次完整唤醒周期（刷新显示 + 计算 + 采集）应在**数 ms 量级**——其中显示重写
  约 1–3 ms（受 HT1621 串行时序下限约束，见 drivers/ht1621.c），其余为 µs–ms 级。

4 秒提供了三个数量级的余量，同时保证卡死后 4 秒内自动恢复。

> TODO: 超时时间常量集中定义，便于调整；用长耗时操作与强制卡死试验验证
> （不误复位 + 卡死后 4 s 内自恢复），完成条件为实测数据（§11）。

> NOTE: IWDG 由 LSI 驱动；LSI 标称 37 kHz，全温区范围约 26–56 kHz，
> 因此分频 256、重装 578（标称 4.0 s）对应的实际超时约 **2.6–5.7 s**，
> 比 ±5% 宽得多。主循环空闲期最长一次 Stop 是显示重写期限（2 s），
> 最坏情况下仍留有余量；实机电流与超时口径见 §11。

### 7.4 RTC 不可用时的降级取舍

LSE 起振失败（时钟晶振损坏/虚焊）时 RTC 与闹钟都不可用，只剩 PA10 EXTI
一个唤醒源。此时若仍启动 IWDG，唯一的 Stop 会无限期持续，IWDG 每 4 s
把设备复位一次，形成复位循环（每次冷启动还额外等 3 s LSE 超时）。

**取舍：仅当 RTC 走时可用时才启动 IWDG**，并在启动时锁存故障
（DOT5 + 空数字位，见 §3.1）；串口用 SysTick 近似时基维持会话超时，
现场仍可读 GET_STATUS 定位问题。该降级设备本来就需要返修/换电池处理，
失去 IWDG 兜底不改变处置路径。

## 8. 时间与对时的正确性

- RTC 用 LSE（X1）+ C4/C5 = 22 pF。
- 晶体精度 ±20 ppm（25 °C），温度漂移约 −0.04 ppm/°C²。
- **30 ppm ≈ 2 分钟/月**；若核验端按 ±30 s 严格比对，建议 1–2 周对时一次；
  打卡场景通常可放宽比对窗口，活动前对时一次即可。
- 片内 RTC 有 1 ppm 分辨率的数字校准，可补偿单一温度点的固定偏差；
  温度变化引起的漂移无法用固定校准值消除。
- 对时（SET_TIME）写整秒 + RTC_SHIFTR 对齐亚秒相位；RTC_SSR 只读，不能直接写
  亚秒计数器。量化误差 ≤ 3.9 ms，SHIFTR 生效延迟 ≈7.8 ms 已在固件中补偿；
  回读自检判据 100 ms，覆盖链路单向时延（serial-protocol.md §5.4）。

换电池必然丢失时间（无 VBAT、无备份电容），需要重新对时 —— 这是已接受的限制。

## 9. 资源预算

构建实测（`-Os`，arm-none-eabi-gcc 16.2.0）：

| 段 | 大小 |
|----|------|
| `.isr_vector` | 184 B |
| `.text` | 912 B（骨架）→ **≈ 11.8 KB（主循环接线后）** |
| `.rodata` | 32 B（骨架）→ **132 B（主循环接线后）** |
| **Flash 合计** | 骨架 ≈ 1.1 KB；**主循环接线后 ≈ 12.1 KB / 32 KB** |
| `.data` + `.bss` | 4 B（骨架）→ **8 B + 208 B（主循环接线后）** |

主循环接线前按模块估算：HMAC-SHA1 约 2–3 KB、TOTP + Base32 约 1 KB、
协议状态机约 2–3 KB、RTC/电源/看门狗约 2 KB、渲染 + 字形表约 1 KB、电量约 0.5 KB。
实测 12.1 KB 落在估算区间内，余量约 20 KB。

**栈预算：链接脚本保证 `.data/.bss` 之后至少留 1 KB 栈空间**（超限直接链接失败）。
